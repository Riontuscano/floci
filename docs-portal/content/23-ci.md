# CI and automated tests

Floci's fast start and small image make it practical to run on every CI job.

## GitHub Actions

```yaml
name: test
on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    services:
      floci:
        image: floci/floci:latest
        ports:
          - 4566:4566
    env:
      AWS_ENDPOINT_URL: http://localhost:4566
      AWS_REGION: us-east-1
      AWS_DEFAULT_REGION: us-east-1
      AWS_ACCESS_KEY_ID: test
      AWS_SECRET_ACCESS_KEY: test
    steps:
      - uses: actions/checkout@v4
      - name: Wait for Floci
        run: |
          for i in $(seq 1 30); do
            curl -fsS http://localhost:4566/_floci/health && exit 0
            sleep 1
          done
          exit 1
      - name: Seed resources
        run: |
          aws s3 mb s3://uploads
          aws sqs create-queue --queue-name orders
      - uses: actions/setup-node@v4
        with:
          node-version: 22
      - run: npm ci
      - run: npm test
```

## GitLab CI

```yaml
test:
  image: node:22
  services:
    - name: floci/floci:latest
      alias: floci
  variables:
    FLOCI_HOSTNAME: floci
    AWS_ENDPOINT_URL: http://floci:4566
    AWS_REGION: us-east-1
    AWS_ACCESS_KEY_ID: test
    AWS_SECRET_ACCESS_KEY: test
  script:
    - npm ci
    - npm test
```

## Testcontainers

Testcontainers starts a fresh Floci per test class or suite, which avoids shared state between tests.

| Language | Package |
|---|---|
| Node.js | `@floci/testcontainers` |
| Java | `io.floci:testcontainers-floci` |
| Python | see the [Python guide](https://floci.io/floci/testcontainers/python/) |
| Go | see the [Go guide](https://floci.io/floci/testcontainers/go/) |

## Tips

- Use `FLOCI_STORAGE_MODE=memory` (the default) in CI for clean, fast runs.
- Give each parallel test worker its own 12-digit `AWS_ACCESS_KEY_ID` to isolate their resources on one Floci.
- Pin the image tag so CI does not change behavior unexpectedly.
